# P-11 Safeguarding: erase and export cover all child data

**What/why.** Deleting a child (or exporting their data) missed several collections. Now the full list is a manifest in code and a self-test fails if it drifts.

**Complete child-data list** (`HUB_COLLECTION_PRIVACY` in `server/src/lib/hubPrivacy.ts`):
- Deleted by `childId`: hubEnrolments, hubSubmissions (+ images with submissionId), hubFlashcardReviews, hubAttempts, hubMastery, **hubDoubts**, **hubFlashcardAssignments**, hubToolStates (ownerKey).
- Scrubbed (child removed, doc kept): hubLessons (childIds, attendance, **liveAnswers.<id>**), hubGroups, hubFamilyInvites, hubBoards (child's elements, **plus the image docs behind them**), hubHomework.assignedChildIds.
- **notifications**: tutor alerts about the child's doubts (ref = doubt id) and the family's learning alerts deep-linked to this child alone.
- No child data: hubAssessments, hubBoardTemplates, hubFlashcards, hubNcTags, hubNotes, hubPings, hubQuestions, hubToolEvents, hubTopics.

**Export** now also returns learningDoubts, learningFlashcardAssignments, learningGroups, learningInvites, learningBoards (counts/kinds of the child's marks), learningHomeworkAssignments, learningToolStates, learningNotifications, and per-lesson liveAnswers (own child only).

**Files.** `server/src/lib/hubPrivacy.ts`, `server/src/hubSelfTest5.ts` (new), `e2e/learning-hub-teaching.spec.ts`. No `my.ts` change was needed (it already calls `eraseChildLearning`).

**Self-test.** `cd server && node_modules/.bin/tsx src/hubSelfTest5.ts` fails if a `hub*` collection used in server/src is not in the manifest, or a child-keyed one is not erased and exported. Verified red by removing hubDoubts from the erase list.

**Revert.** `git revert` the commit; additive only.

**Known gaps.** Notifications that name several children at once (multi-child family alerts) are not removed; owner to review (11-open-questions.md).
