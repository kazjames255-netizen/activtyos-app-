# R-2 One Mark queue

Branch `teaching-hub-redesign`. Additive and reversible: no schema, no server change, the three old queues untouched.

## What changed
- `features/learninghub/mark/useMarkItems.ts`: reads the EXISTING endpoints (`GET /homework/inbox`, `GET /attempts?status=pending_marking`, `GET /assessments?ids=` for titles and quiz/starting-quiz kind) and merges them, longest-waiting first. Read-only.
- `features/learninghub/mark/MarkQueue.tsx`: one list, each row = child, kind chip (Homework / Quiz answers / Starting quiz), what, how long waiting. A row opens the EXISTING UI in place: `MarkDialog` for a hand-in, `MarkForm` (now exported from `quiz/MarkingQueue.tsx`, one word changed) for written answers. "Mark & next" (dialog) and "Save and next" (form) walk to the next row whatever its kind. "Next to mark" at the top opens the longest-waiting row in one tap.
- Homework tab (`TutorHomework.tsx`): first segment is now **To mark (N)**, then Inbox, then Set homework.
- Home (`TutorHome.tsx`): the three to-mark attention rows (Homework, Written answers, Starting quizzes) keep their own counts and labels but all land on the queue (`requestMarkQueue()` in `hubIntent.ts`, one-shot like the overdue filter).
- Tab badge: the Homework tab shows the total waiting (`LearningHubApp.tsx`).

## Why the Homework tab
It already owns the biggest of the three queues and the "Mark & next" flow, it is a tab the tutor already reaches by position, and no tab moved (P-10 order preserved). A new tab would shift every tab to its right; a section on Home would break the "do not reorder TutorHome" condition. The queue is a segment, so Inbox (with its filters, Marked and Not handed in) is still one tap away.

## What is preserved
- `resolveTab` and the alias map untouched. `?tab=diagnostic|quizzes|homework|questions&open=...` unchanged: Quizzes > Marking and Starting quizzes > Marking are still there and still work (asserted in the spec).
- Group card "Homework" tile, Home's Overdue tile and a `viewGroup` still open on Inbox as before (the queue is only the default when nothing asked for something else).
- Feedback chips, "Use the quiz score", "The family is notified when you save": untouched (same dialog). No new taps or confirms on marking.

## Tap counts (derived from code, not measured)
Scenario from X3-04: clear 3 hand-ins, 3 quiz written answers, 2 starting-quiz written answers.
| Step | Before | After |
|---|---|---|
| Get to the first item from Home | 2 (tab, row) | 2 (Home row, "Next to mark") |
| Each item within a queue | score + Save-and-next = 2 | 2 (unchanged) |
| Switch from homework to quiz answers | Home/tab (1) + Quizzes tab (1) + Marking sub-tab (1) + row (1) = 4 | 0 (next row is next) |
| Switch from quiz answers to starting quiz | Starting quizzes tab (1) + Marking sub-tab (1) + row (1) = 3 | 0 |
| Back out to the list after each queue | 1 per queue | 0 |
| Whole job (8 items) | about 28 (X3-04) | about 18: 2 to start + 8 x 2 |

The saving is the two queue switches (7 taps) plus the "back to queue" and lookups between them; per-item cost is deliberately unchanged.
