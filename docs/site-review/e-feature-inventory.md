## 2. Feature inventory by area

### Bookings and storefront
- Listing wizard: camps, classes, blocks (term/weekly), single sessions, trips, "subscription"-type listings, passes/tickets, add-ons/extras, age bands, capacity, ratio groups (`features/listings/ListingWizard.tsx`, `server/src/routes/listings.ts`, `blocks.ts`). Public storefront `/store/{id}`, booking page `/book/{id}`, embed widget `public/embed.js`.
- Basket checkout, multiple children, card via Stripe, pay-link/invoice pay page (`app/pay`, `features/money/PayPage.tsx`), Wallet credit, discount codes (`server/src/lib/discountCodes.ts`, `routes/discounts.ts`; e2e `coupons.spec.ts`), referrals (`routes/referral.ts`), memberships (benefit on join), sibling/block/early-bird rules, partial cancellation + refund calc (`docs/partial-cancel-handoff.md`, e2e `booking-lifecycle.spec.ts`), booking cut-offs, age-range enforcement at booking (`routes/my.ts:940`).
- Waitlist (see above), automatic session reminders and payment-due reminders (`server/src/lib/autoEmails.ts`, `sweeps.ts`), receipts (`features/parent/paymentReceipt.ts`).
- Bulk family import from CSV/spreadsheet + invite emails (`features/customers/FamilyImport.tsx`). CSV export of bookings/families (`features/bookings/ExportWizard.tsx`, `FamiliesExport.tsx`).
- **Not found:** gift vouchers (sell), Stripe-billed recurring memberships/subscriptions, custom domain, SMS broadcast.

### Comms
- Messages (1:1 and broadcast, scoped; e2e `messages-broadcast.spec.ts`, `comms-scoping.spec.ts`, `comms-ui.spec.ts`), Email campaigns with audiences, merge fields (`lib/mergeFields.ts`: ParentName, ChildName, ProviderName, ListingName, SessionDate, VenueName, BookingRef), open-tracking pixel, unsubscribe + consent (`email-audiences.spec.ts`, `email-compliance.spec.ts`), Newsfeed/posts with acknowledgement, Moments (photos; photo consent enforced server-side `routes/moments.ts`), staff announcements, in-app bell notifications, support inbox to HQ.

### On the day and safeguarding
- Registers: sign in/out, absent, "not arrived", collected-by (free text on server), collection password shown to staff on the register (display only, not a hard gate), allergy/medical/SEND on the row, roll call, ratio groups (`routes/registers.ts`, `ratios.ts`; default bands under 2 = 1:3, 2 = 1:4, 3-4 = 1:8, 5-7 = 1:8, 8+ = 1:10, overridable; `server/src/lib/ratios.ts`). e2e `dayops.spec.ts`, `safeguarding.spec.ts`.
- Enforced by the API (verified in code): **no dose without parental consent** (`routes/medications.ts:349`, 409); **trip cannot be signed off/completed with any child's consent pending** (`routes/trips.ts` ~376-392, 409; e2e `trips-consent.spec.ts`); **rostering refused for a person with an expired first-aid/safeguarding certificate or (default) no DBS on file** when `requireCompliance`/`requireDBS` is on (`routes/shifts.ts`, `lib/staffPolicy.ts`; defaults ON). Cleared-to-start gate and unresolved-reference-concern block also in `staffPolicy.ts`.
- Concern logging notifies the named DSL / deputy automatically (`lib/dslAlert.ts`); LADO/MASH numbers on the form; PDF export of a concern; deletion of a DSL-decided record is audited (`lib/incidentDeletionAudit.ts`). Accidents/first aid with body map, parent notified, optional "require acknowledgement" (`incidents.ts`). Medication/MAR with parent notify (`medications.ts`). Meals with allergen matching and parent pre-order (`routes/meals.ts`, `mealsShop.ts`, `mealMenus.ts`). Trips with consent, headcount.
- Not found in code: a RIDDOR decision field on the accident form, captured parent signature on accident form (site mockup shows both).

### Staff, HR, learning
- Rota/schedule (`routes/rota.ts`, `shifts.ts`), availability, leave with UK 5.6-week entitlement engine (`lib/holiday.ts`), timeclock with breaks, lateness auto-deduct rules and staff corrections (`routes/timeclock.ts`; e2e `timeclock-staff-correction.spec.ts`), timesheets feeding payroll, onboarding / safer recruitment records (DBS, references, right to work, ID scans), applications, appraisals (two-sided), expenses claims, payslips, documents and policy read-and-confirm, credentials/certificate tracking with expiry sweep, Learning Centre course library (SEED_LIBRARY ids c1..c66 in `features/learning/courseContent*.ts`; the exact live count is not pinned - the site says 39) with certificates. Courses are described in code as "CPD-style"/"CPD course"; **no CPD accreditation body certificate found in repo**.

### Franchise and network
- Franchise invites, territory areas drawn on a map (postcode/region rings) with HQ approval (`routes/franchises.ts`: "a franchise can't self-approve"), **approximate overlap warning (read-only), not a hard block** (`features/franchise/FranchiseTerritoriesApp.tsx`), per-franchise brand (logo/accent via `lib/brand-theme.ts`), feature control per franchise, HQ dashboard rollup with by-franchise charts and attention list (`HoDashboardApp.tsx`), Royalties/Split fees report (basis revenue or per-booking), franchise isolation proven by `e2e/franchise-isolation.spec.ts`. Franchise portal has its own payroll, Stripe account, staff.
- **Schools/MAT view: there is no "Trust office" product.** No "Schools", "Term dates", "Take-up", "Invite schools" nav items exist; schools use the Company/Franchise portal. The `schools.html` dashboards are conceptual mock-ups.

### Money
- Finance & analytics, Money in (purchase/sales), Money out (expenses/suppliers/POs), Invoices (raise, send, pay link, PDF), Reconciliation ledger for non-card methods (TFC, voucher, bank transfer, cash) with manual tick, Inventory, Split fees, Wallet, refunds computed and logged, subscription self-serve (Stripe Billing, trial, cancel, reactivate; e2e `subscription-billing.spec.ts`), payouts via Stripe Express (provider's Stripe dashboard).

### Learning / Teaching Hub (not on the site)
- Large tutoring product: `learninghub` view in 4 portals plus a parent Learning Hub and child kid-mode: lessons, slide builder, live room/whiteboard, quizzes, homework, flashcards, spaced repetition, games/arcade, curriculum content (memory: 4,679 questions QA'd), assignments, progress, digest emails, 60+ e2e specs `learning-hub-*.spec.ts`, narrated "How it works" films at `/how-it-works`.

### Security and data (all evidenced in `docs/tfc/security-evidence.md`)
- Server-side authorisation only; browser never touches Firestore; role/tenant read from server records each request; per-area permission matrix for staff (`middleware/access.ts`); franchise narrowing; tenant isolation tests (`server/src/isolationTest.mts`, e2e); HQ super-admin email 2FA; impersonation logged; rate limits; zod validation; HMAC signed links; Firebase Auth (passwords never stored by us).
- Encryption: HTTPS at hosts; Firestore at rest by Google; **AES-256-GCM field encryption for staff NI numbers and onboarding bank details only**.
- Audit: payroll audit log (write-only, no screen), DSL-delete audit, impersonation log, TFC payment attempts.
- Known gaps (15) listed in that doc: unencrypted HMRC and accounting tokens, ID/DBS scans not field-encrypted, no Firestore rules file in repo, no security headers in app code, in-memory rate limiter, no independent pen test, no certification.
- Privacy surface: parent "Data & privacy" view = see/download data, **deletion is a recorded request**, not a wipe (`routes/privacy.ts`). Staff onboarding records purged 6 years after leaving by a daily job. No evidence in repo of the 30/90/35-day retention windows stated in the privacy policy.
