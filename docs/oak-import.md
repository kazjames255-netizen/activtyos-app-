Every imported lesson MUST show: "A {subject} lesson by Oak National Academy licensed under Open Government Licence (OGL)" + link https://www.nationalarchives.gov.uk/doc/open-government-licence/version/3/ and keep `source.url`. ## Raw data (crawler output)
`node server/src/oak/crawl.mjs` → `scratch/oak-raw/<programmeSlug>/<unitSlug>__<lessonSlug>.json` (one file per lesson; resumable; 8,279 lessons: Maths, English, Science, French, Spanish, German, KS1–KS4, KS4 = AQA-tagged, Maths KS4 higher+foundation). Fields used: programmeSlug, unitSlug/unitTitle, subjectTitle, keyStageSlug, yearGroupTitle/year (string "1".."11"), examBoardTitle, tierTitle, lessonSlug/lessonTitle, orderInUnit, unitTotalLessonCount, pupilLessonOutcome, keyLearningPoints[{keyLearningPoint}], lessonKeywords[{keyword,description}], misconceptionsAndCommonMistakes[{misconception,response}], teacherTips[{teacherTip}], lessonOutline[{lessonOutline}], transcriptSentences[string], starterQuiz[] / exitQuiz[] (question objects, see below), _sourceUrl, updatedAt. Duplicates: Foundation/Higher (Maths KS4, sciences) and programmes overlap → dedupe by `unitSlug+lessonSlug` within subject+key stage, record every programme it appeared in.

Oak question object: `questionType` ∈ multiple-choice | short-answer | match | order; `questionStem[]` = [{type:"text",text} | {type:"image",imageObject:{secureUrl,…}}]; `answers[<questionType>][]` (multiple-choice: {answer:[stem parts], answerIsCorrect}; short-answer: {answer:[…], answerIsDefault}; match: {correctChoice, matchOption}; order: {answer, correctOrder}); `feedback` (string), `hint`. Images at oaknationalacademy-res.cloudinary.com (`secureUrl`).

## Hub mapping
- **Topic tree** (`hubTopics`): parent = subject + unit? No — parent = `topic` = Oak unit title; subtopic = "Year N" (KS4: "Year 10"/"Year 11" from `year`). Subject label = "Maths" | "English" | "Science" | "French" | "Spanish" | "German". Science KS4 units carry the Oak programme's subject (Biology/Chemistry/Physics/Combined Science) → prefix topic like the existing curriculum ("Biology — <unit>").
- **Lesson** (`hubNotes`, UI name "Lesson"): one per Oak lesson, id `oak-<TID>-<progless>-<lessonSlug>` (deterministic, idempotent). `title` = lessonTitle, `body` = short markdown fallback (outcome, key learning points, keywords, and a `## Lesson plan` section with the plan steps; NO transcript, NO common mistakes) so anything reading `body` still works, PLUS optional structured `lesson` field (steps, keywords, outcome, `plan`, tutor-only `misconceptions` + `teacherTips`, `source:{provider:"oak",url,licence:"OGL-3.0",attribution,programmes,fetchedAt}`) that the new Lesson viewer renders interactively. Keep total doc < 900KB.
- **Questions** (`hubQuestions`): every starter + exit question; multiple-choice→`single` (or `multi` if >1 correct), short-answer→`short` (`answer` + `accepted` from all listed answers, lower-cased/trimmed matching), match→NEW kind `match`, order→NEW kind `order`. Oak `feedback` → `explanation`; `hint` → optional `hint`. Images: keep `image:{url,alt}` pointing at the Oak URL (and a local copy path) until image storage is decided.
- **Quizzes** (`hubAssessments`): per lesson one quiz "Lesson quiz — <title>" = exit-quiz questions; starter-quiz questions are the lesson's "Warm-up" check-ins (stored as questions, referenced from the lesson's structured `lesson.warmupQuestionIds`), not separate quizzes. Per unit, one "Unit check" quiz = up to 12 exit questions sampled across the unit's lessons. Audience = year group of the unit. Flag 2 mid-difficulty exit questions per lesson `diagnostic:true` later (placement papers are built after import).
- **Flashcards** (`hubFlashcards`): one per lesson keyword (front = keyword / "What is <keyword>?", back = Oak description) + cloze cards from key learning points; agents may add a few more per lesson but ONLY facts stated in that lesson. Deduplicate identical fronts inside a unit.
- **Provenance**: every written doc carries `source:{provider:"oak", url, licence:"OGL-3.0"}` and `imported:true` so old vs Oak content can be filtered and un-published without deleting. Never delete existing (non-Oak) content or attempts; unpublish decisions happen after import (owner will review).
- Do not touch booking/invoicing/scheduling. Do NOT run against real tenants until told — target the staging/test tenant only (ask lead for the id).

## Factory (lesson factory, 2026-09-20)
Every Oak lesson gets the pilot's structure: an interactive slide deck (`lesson.slides`) on top of the warm-up + exit quiz + flashcards the importer already wrote, and for priority lessons curated flashcards + a worksheet. Design/measurements: `docs/hub-review/C0-lesson-factory.md`.

**Files.** `server/src/oak/factory/{generate,validate,index,emoji,cli}.ts` (generator, validator, precedence, CLI) · `server/src/oak/crawlSlides.mjs` (Oak slide-deck text + worksheet text/PDF from Google Slides `export/txt|pdf` into `scratch/oak-slides/`, resumable) · `server/src/oak/curated/<unitSlug>__<lessonSlug>.json` (agent-authored rich decks; same key = `unit__lesson`) · `scratch/oak-factory/{AUTHORING,REVIEW}-BRIEF.md` (agent briefs) · `e2e/factory-shots.spec.ts` (visual check).

**Precedence per lesson** (only with `--slides`): hand-built `slides/<lessonSlug>.ts` > curated JSON > generated deck. Without `--slides` no slide deck is written. The raw video transcript is NEVER stored any more (not in `body`, not in `lesson.transcript`): see "Lesson plan" below. Curated lessons also write their own flashcards (`...-c-<tid>-x<n>`) and the worksheet note + short-answer quiz (+ PDF attachment if `scratch/oak-slides/_pdf/<subject>-<ks>/<unit>__<lesson>.pdf` exists and is <= 700KB).

**Commands** (from `server/`; all idempotent, deterministic ids, re-run = update in place):
```
npx tsx src/oak/factory/cli.ts check [--subject Maths --keystage ks2 --unit s --lesson s]   # generate + validate every deck (no Firestore), prints per subject x key stage; exit 1 on any invalid deck
npx tsx src/oak/factory/cli.ts show <lesson-slug>        # readable generated/curated deck        cli.ts dossier <unit__lesson>   # everything an authoring agent may use
npx tsx src/oak/factory/cli.ts curated                   # validate every curated/*.json (schema, keys, no case-only worksheet answers)
node src/oak/crawlSlides.mjs [--pdf] [--curated]         # (re)fetch slide/worksheet text; --pdf --curated = worksheet PDFs of curated lessons only
npx tsx src/oak/import.ts <tenantId> --subject Maths --keystage ks2 --slides [--add-kinds]     # load (staging first)
npx tsx src/oak/import.ts check <tenantId> --subject Maths --keystage ks2 --slides --deep       # verify what is stored (slow on a big tenant: ~9 min for 360 lessons)
```
Load one subject to a real tenant only when the lead says so: `--real` is required for `7jG2XO3cOD3VtoL8YfFY` / `jYp5XNZGT7bgSUMuEgHN`, e.g.
`for ks in ks1 ks2 ks3 ks4; do npx tsx src/oak/import.ts <realTenant> --real --subject Maths --keystage $ks --slides; done` (Maths ~7.5k docs per key stage, ~90-240 s each; whole library ~150k docs / ~36 min).

**Slide pictures (F1 policy, 2026-09-20).** A slide gets a picture ONLY when a verified match exists, otherwise none (a missing picture is fine, a wrong one is a severe bug). Verified sources: the purpose-drawn SVG library `server/src/oak/factory/art/` (127 diagrams with exact `concepts`, `avoid`, `numeric`, family rules; slides store only `pics: [{id}]`, rendered by `features/learninghub/lesson/slides/SlideArt.tsx`) and the literal-emoji allow-list `art/allowlist.ts`. Never on practice/check/interactive slides; the author's art in curated/hand-built decks is ignored (`applyArtPolicy` in `deckFor` and in the importer), and `verifyArt` rejects any deck whose art is not verified. Tools: `npx tsx src/oak/factory/art/cli.ts check|doc|sheet`, `art/fixCurated.ts`. Full write-up: `docs/hub-review/F1-images.md`.

**Facts to remember.** The generator never uses the transcript/slide text/misconceptions (unsafe: teacher chatter, wrong distractors) — only outcome, key learning points, keywords, outline. Oak's own data can be wrong (a wrong key learning point, typos, contradicting figures): generated decks repeat Oak's key learning points verbatim, the curated lane (author + independent reviewer agent) corrects/omits them. The hub's short-answer marker (`hubScoring.normText`) trims + lower-cases and is accent-sensitive: worksheet answers must not depend on letter case (`cli.ts curated` rejects genotype-style answers). Slide block `{}` and `**` are markup: sets use the ornament brackets. Worksheet PDFs average 250KB (all 7,470 would be ~2.5GB in Firestore as base64), so they are attached for curated lessons only. Load on this machine is high during agent waves (load average 250-400): Playwright/API calls can time out then.

**Quality layer (Q1 review, 2026-09-20; Maths + Science).** `factory/quality.ts` cleans Oak's facts BEFORE the generator / planner see them (`factsFromRaw`, `planFactsFromRaw`): `tidy()` (superscripts for `x^2`, HTML tags, stray punctuation, known Oak typos, repeated function words), `CORRECTIONS` (Oak statements that are wrong: corrected to the true form or dropped; each entry says why), `cleanPoints` (drops blank stems `___`, teacher objectives, spec fragments with no verb, references to "this lesson"/stem sentences, duplicates), `cleanKeywords` (drops lesson-context sentences, definitions with blanks, and definitions that are really another keyword's: Oak swapped Numerator/Denominator). Interactive items are stricter: `maskDefinition` masks only whole-word forms of the key word and refuses a clue that still shows a form of it; wrong options must agree with the blank in a/an and singular/plural, must not be synonyms / sub-types / acronyms of the answer, and (cloze) must not be a topic word of the lesson; an outline heading is only used as a slide title when it shares a content word with the points under it. `validate.ts` re-checks all of this on the finished deck. Full write-up and defect rates: `docs/hub-review/Q1-generated-qa.md`. Rule of thumb when adding rules: a rule may only ever REMOVE content (an item, a point, a title), never invent it.

## Lesson plan (replaces the raw video script)
Every imported lesson carries `lesson.plan` (type `LessonPlan`, `features/learninghub/lesson/plan.ts`): an ordered, simplified step-by-step plan a tutor can teach from: **warm-up and goal → teaching steps (one per part of the lesson) → guided practice → independent practice (the lesson quiz) → plenary**; each step has `title`, `minutes`, `doThis[]` (1-4 short sentences), optional `say`, `keyIdeas[]`, `keywords[{term,meaning}]`, `checkFor{ask,lookFor}`, `examples[]` and `recap[]` (the same step in the child's words). Plus `commonMistakes[{mistake,fix}]` and `watchOut[]` (tutor-only; the API strips both from a family's payload, the steps stay: they are the student's "Recap: step by step" on the Done step). Tutors cannot edit the plan in v1 (PUT keeps it; PATCH only takes `widget`/`slides`).
- **Precedence**: hand-written `server/src/oak/plans/<lessonSlug>.ts` (`PLANS_BY_LESSON`) > curated JSON optional `"plan"` key > DERIVED by `server/src/oak/factory/plan.ts` (deterministic, no LLM). `factory/index.ts planFor()` does the choice and validates; an invalid plan is never written (the lesson is imported without one, counted in `no plan:` in the importer report).
- **Derived plan = only Oak's own words**: outcome, key learning points (allocated to outline headings with the deck generator's `allocate`), keyword definitions, outline headings, teacher tips (`watchOut`), misconceptions (`commonMistakes`); everything else is one of a fixed set of TEMPLATE instructions with no lesson facts in them. The video transcript is NOT used as text (sampled transcripts contain speech-to-text errors and pupils' wrong statements); the only thing taken from it is PURE ARITHMETIC sentences ("6 plus 4 is equal to 10") and only when the arithmetic evaluates TRUE. Tips/misconceptions that mention Oak's video/slides/worksheets/task codes/learning cycles/names/chatter are dropped.
- **Validator** (`validatePlan`): shape (3-9 steps, order, sizes), no chatter / Oak-resource tokens, every number occurs in Oak's data for the lesson, and for derived plans every fact is verbatim from the lesson data and every other word is a known template. Hand-written plans get shape + chatter + numbers (so they must be re-verified by hand against `cli.ts dossier <key>`).
- **CLI** (`cd server`): `npx tsx src/oak/factory/plancli.ts check [--subject S --keystage ks2]` (all 7,470 lessons: stats + every invalid plan), `show <slug>`, `sample <N> --seed k`, `plans` (validate hand-written + curated plans).
