# Curriculum content brief — KS1–KS5 (Maths, English, Science, Languages)

Owner request: original, curriculum-aligned content for the Learning Hub across **Key Stages 1–5** (school years 1–13) for **Maths, English, Science and Languages (French, Spanish, German)**. The KS2 Maths spec (`docs/curriculum-ks2-maths-spec.txt`, DfE National Curriculum, Open Government Licence v3.0) is the model: per topic × year a **quiz**, a **course note**, **flashcards**, and per-year **placement (diagnostic) papers** that the seeder assembles from questions flagged `diagnostic:true`.

Content is **original** (written for ActivityOS), *aligned to* the published programmes of study (KS1–KS4: DfE National Curriculum programmes of study; KS5: DfE GCE AS/A-level subject content) — **never copy exam-board questions, past papers, mark schemes or textbook text**; write your own "in the style of". No copyrighted images (draw your own diagrams).

## Format (already built — follow exactly)
`server/src/curriculum/types.ts` (CTopic / CYear / CQuestion), validator `server/src/curriculum/validate.ts`, README. **One file per topic per pack**: `server/src/curriculum/<pack>/<key>.ts` exporting `TOPIC: CTopic`. Files in different packs with the same `subject` + `topic` name **merge** (that's how KS1 / KS3 join KS2). The validator scans every pack folder. Run it often: `cd server && npx tsx src/curriculum/validate.ts <pack>` — it must end with `0 problem(s)`. Do NOT use `__dirname` / `require.main` in scripts (the server package is ESM under tsx; use `import.meta.url` + `fileURLToPath`).

Per topic-year (`CYear`): `year` (1–13), optional `subtopic` label (e.g. "GCSE (Years 10–11)") and `yearsCovered`, `objectives[]` (condensed, from the programme of study), `note {title, body}` (markdown, ≥120 words: what to know + 2–3 worked examples + a small table/list; KS4–5 notes 200–350 words), `quiz {title, questions[]}` (**10 questions**; KS4–5 **12–14**; keys like `npv-y6-03` = `<topickey>-y<year>-NN`, globally unique), `flashcards[]` (8–12; front = short prompt/term/cloze, back = crisp answer/rule).

Per question: `kind` ∈ single (4 options, 1 right) · multi (2+ right, not all) · short (typed answer, put spellings in `accepted`) · number · written (tutor-marked, Year 7+, **at most 1 per quiz**, mark scheme in `explanation`). `explanation` states the METHOD/reason in 1–3 child-appropriate sentences. `difficulty` 1/2/3 spread ≈ 3 : 5 : 2 (KS4–5: 2 : 5 : 3 with level 3 ≈ top-grade). Correct options spread across positions. Distractors reflect real misconceptions. Exactly **2 questions per topic-year flagged `diagnostic: true`** (representative, mid difficulty). Optional `image {file, alt}` — PNGs ≤200KB drawn by you (SVG → PNG via the Playwright-chromium technique in `scratch/hub-demo-images/generate.mjs`; read it) into `scratch/curriculum-images/<pack>/`; **alt text mandatory**; the image must not leak the answer; **Read every PNG you make** and fix clipping/overlap/legibility. British English (£, metric, UK spelling). Plain text with unicode — no LaTeX, no HTML (use ×, ÷, ½, ², √, ≥, →, ⇌, Δ, é, ñ, ü, ß, 你好, etc.). KS1 (ages 5–7): very short sentences, simple words, concrete objects (emoji like 🍎 are fine), no more than 2 lines per prompt.

## Quality rules (children learn from this — a wrong key is the worst bug)
1. **Verify every answer independently.** Where an answer is computable (arithmetic, science calculations, unit conversions, sequences, stats, dates) write a checker `server/src/curriculum/<pack>/_check_<pack>.ts` (leading underscore = skipped by the validator) that recomputes the key from the question data. For language content, re-read every item as a native-level teacher: spelling, accents, gender/agreement, verb forms, idioms; provide `accepted` variants (e.g. "j'ai" vs "j’ai") for short answers. For English/science facts re-read skeptically (no folklore, no outdated facts).
2. Exactly one defensible correct option; distractors clearly wrong; no two questions give away each other's answers; no question depends on an image you didn't supply.
3. Age-appropriate reading level; inclusive names/contexts; no brands, no politics/religion controversy (RE excluded), nothing distressing.
4. Cover the objectives you list; keep each topic-year to its year's scope (don't leak next year's content).
5. Notes are teaching material (clear, warm, correct); flashcards are retrieval practice (one fact per card).
6. Aim for variety: worked-example items, application, reasoning ("explain why", "which is the mistake"), a few 2-step problems.
7. You may not edit other agents' files. If you need to fix something outside your pack, message the lead in your report.

## Coverage & placement
Per subject the seeder builds, for each year N, a **placement paper** from 1–2 `diagnostic:true` questions of every topic that has content in year N and N−1 (scored per topic). So keep topic names consistent, flag diagnostics well, and give each topic-year real coverage.

## Definition of done (each agent)
`validate.ts <pack>` → 0 problems; your `_check` script passes; every PNG viewed; a short report: files, counts (questions / notes / flashcards / images per topic-year), how you verified, doubts. Do not touch Firestore, do not restart servers, do not run Playwright. Machine is shared and slow — keep scripts light.
